# Native bridges (iOS NetworkExtension + Android VpnService + Push)

The Rust crate at `src-tauri/src/mesh.rs` exposes Tauri commands the JS layer calls
(`mesh_enroll`, `mesh_start`, `mesh_stop`, `mesh_status`, `mobile_get_push_token`).
The actual *tunnel construction* and *platform push token retrieval* must happen
in platform-native code that's outside the Rust crate.

This file is the cookbook for adding that platform code **after running**:

```bash
npm run tauri -- ios init       # macOS only
npm run tauri -- android init
```

Those commands materialize `src-tauri/gen/apple/` and `src-tauri/gen/android/`
with Xcode and Android Studio projects respectively. The notes below tell you
what to add to those generated projects.

---

## iOS — NetworkExtension (PacketTunnelProvider)

### 1. Add a new target in Xcode

`src-tauri/gen/apple/operator-mobile.xcworkspace` → File → New → Target →
**Network Extension** → Packet Tunnel Provider. Name it `WireGuardTunnel`.
Bundle ID: `com.papercuspai.operator.mobile.WireGuardTunnel`.

Apple requires:
- Both the main app and the extension to have the **Network Extensions** capability with **Packet Tunnel** checked.
- A **shared App Group** (e.g. `group.com.papercuspai.operator.mobile`) so the main app can pass config to the extension.
- An entitlement: `com.apple.developer.networking.networkextension` with `packet-tunnel-provider`.

### 2. PacketTunnelProvider.swift

```swift
import NetworkExtension
import os.log

class PacketTunnelProvider: NEPacketTunnelProvider {
    private var wgConfig: String?

    override func startTunnel(options: [String : NSObject]?, completionHandler: @escaping (Error?) -> Void) {
        guard let providerProtocol = self.protocolConfiguration as? NETunnelProviderProtocol,
              let pc = providerProtocol.providerConfiguration,
              let config = pc["wg-config"] as? String else {
            completionHandler(NSError(domain: "WG", code: 1, userInfo: [NSLocalizedDescriptionKey: "missing wg-config"]))
            return
        }
        self.wgConfig = config

        // Use WireGuardKit (https://git.zx2c4.com/wireguard-apple) — Apple-blessed Swift package.
        // Add via SPM: https://git.zx2c4.com/wireguard-apple
        // Then: WireGuardAdapter parses the conf string and brings up the tunnel.

        let adapter = WireGuardAdapter(with: self) { logLevel, message in
            os_log("%{public}s", log: .default, type: .debug, message)
        }
        adapter.start(tunnelConfiguration: try! TunnelConfiguration(fromWgQuickConfig: config)) { error in
            completionHandler(error)
        }
    }

    override func stopTunnel(with reason: NEProviderStopReason, completionHandler: @escaping () -> Void) {
        // adapter.stop { _ in completionHandler() }
        completionHandler()
    }
}
```

### 3. Bridge from Rust into the extension

The main app holds an `NETunnelProviderManager`; calling `mesh_start` from JS
should invoke a small Swift bridge that creates / loads / starts the manager:

```swift
// In the main app target (not the extension):
import NetworkExtension

@objc class MeshBridge: NSObject {
    @objc static func startTunnel(wgConfig: String, completion: @escaping (Error?) -> Void) {
        NETunnelProviderManager.loadAllFromPreferences { managers, _ in
            let mgr = managers?.first ?? NETunnelProviderManager()
            let proto = NETunnelProviderProtocol()
            proto.providerBundleIdentifier = "com.papercuspai.operator.mobile.WireGuardTunnel"
            proto.serverAddress = "papercusp-mesh"
            proto.providerConfiguration = ["wg-config": wgConfig]
            mgr.protocolConfiguration = proto
            mgr.localizedDescription = "Papercusp Mesh"
            mgr.isEnabled = true
            mgr.saveToPreferences { err in
                if let err = err { completion(err); return }
                mgr.loadFromPreferences { _ in
                    do {
                        try mgr.connection.startVPNTunnel()
                        completion(nil)
                    } catch { completion(error) }
                }
            }
        }
    }
}
```

Wire `mesh::mesh_start` in `src-tauri/src/mesh.rs` (the `#[cfg(target_os = "ios")]` block)
to call into `MeshBridge.startTunnel` via Tauri's iOS plugin proxy mechanism.

### 4. Push token (APNs)

In the AppDelegate (auto-generated by `tauri ios init`), add:

```swift
func application(_ application: UIApplication,
                 didRegisterForRemoteNotificationsWithDeviceToken deviceToken: Data) {
    let token = deviceToken.map { String(format: "%02.2hhx", $0) }.joined()
    // Stash for the Rust command:
    UserDefaults.standard.set(token, forKey: "apns_token")
}
```

Then in `mesh::mobile_get_push_token` (iOS branch), read from `UserDefaults` via Tauri's iOS bridge.

## Android — VpnService (foreground service)

### 1. Manifest entries

`src-tauri/gen/android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE"/>
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>

<service
    android:name=".WireGuardVpnService"
    android:permission="android.permission.BIND_VPN_SERVICE"
    android:foregroundServiceType="specialUse"
    android:exported="false">
    <intent-filter>
        <action android:name="android.net.VpnService"/>
    </intent-filter>
</service>
```

### 2. WireGuardVpnService.kt

Use `wireguard-android` (https://github.com/WireGuard/wireguard-android), the
upstream WireGuard Android library. Add to `build.gradle`:

```gradle
implementation 'com.wireguard.android:tunnel:1.0.20240909'
```

```kotlin
package com.papercuspai.operator.mobile

import android.content.Intent
import android.net.VpnService
import com.wireguard.android.backend.GoBackend
import com.wireguard.android.backend.Tunnel
import com.wireguard.config.Config

class WireGuardVpnService : VpnService() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        val configString = intent?.getStringExtra("wg-config") ?: return START_NOT_STICKY
        val config = Config.parse(configString.byteInputStream())
        val backend = GoBackend(applicationContext)
        val tunnel = object : Tunnel {
            override fun getName() = "papercusp-mesh"
            override fun onStateChange(newState: Tunnel.State) { /* notify Rust via JNI */ }
        }
        Thread { backend.setState(tunnel, Tunnel.State.UP, config) }.start()
        return START_STICKY
    }
}
```

### 3. JNI bridge from Rust

In `src-tauri/src/mesh.rs`, the Android branch of `mesh_start` uses the `jni`
crate to call into `WireGuardVpnService` via an Intent. Tauri 2 generates an
Android plugin scaffold under `src-tauri/gen/android/app/src/main/java/.../<pluginname>/`
when you run `cargo tauri android add plugin <name>` — easier than raw JNI.

### 4. FCM push token

Add Firebase to the Android project:

1. Create a Firebase project; register the package `com.papercuspai.operator.mobile`.
2. Drop `google-services.json` into `src-tauri/gen/android/app/`.
3. Add the Firebase BOM + `firebase-messaging` to `build.gradle`.
4. Add a `MyFirebaseMessagingService` that calls back into Rust on `onNewToken`.

## Wiring summary

| Tauri command | iOS | Android |
|---|---|---|
| `mesh_enroll` | HTTP from Rust (no native bridge needed) | HTTP from Rust |
| `mesh_start` | Calls `MeshBridge.startTunnel` (Swift) → `NETunnelProviderManager` | Sends Intent to `WireGuardVpnService` (Kotlin) |
| `mesh_status` | Reads from shared App Group keystore | Reads from shared prefs |
| `mesh_stop` | `NETunnelProviderManager.connection.stopVPNTunnel()` | `stopService(Intent(this, WireGuardVpnService::class.java))` |
| `mobile_get_push_token` | `UserDefaults["apns_token"]` (set by AppDelegate) | `FirebaseMessaging.getToken()` |

## Server-side prerequisites (operator)

Mobile API depends on a few env vars + DB grants that the operator's
default `bin/prod` does **not** set up. The mobile e2e sweep (May 2026)
turned up each of these as a 500 — they're listed here so future
agents don't reintroduce them.

### `.env.local` must include

```
MOBILE_JWT_SECRET=<64+ char base64url>
```

Without this, `/api/mobile/pair` 500s under `NODE_ENV=production` — the
dev fallback (random per-process secret) is gated on `NODE_ENV !==
'production'`.

Generate:
```
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

### Postgres `harness_app` role grants

Migrations `009_mobile_devices.sql` and `010_mobile_read_grants.sql`
add the necessary GRANTs. If the DB was created before those landed,
run by hand:

```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON harness_shared.mobile_devices       TO harness_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON harness_shared.mobile_push_tokens   TO harness_app;
GRANT SELECT ON harness_shared.harness_status      TO harness_app;
GRANT SELECT ON harness_shared.harness_lanes       TO harness_app;
GRANT SELECT ON harness_shared.harness_smoke_test  TO harness_app;
GRANT SELECT ON harness_shared.harness_plan_review TO harness_app;
GRANT SELECT ON harness_shared.operator_scans      TO harness_app;
GRANT SELECT ON harness_shared.harness_registry    TO harness_app;
```

Without these, mobile route handlers 500 with `permission denied for
table <name>` before RLS even runs (PG checks table ACL first).

### Browser-dev proxy

`apps/operator-mobile/vite.config.ts` proxies `/api → :3070` so that
cross-origin pairing fetches go same-origin (the mint-pair-token
endpoint relies on the operator's session cookie, and CORS preflight
isn't configured on `:3070`). The proxy also forwards
`/api/mobile/voice → :3056` because voice WS lives on a separate
port. Native Tauri webview hits the operator host directly — the
proxy is browser-dev-only.

### Mobile API base resolution

`apps/operator-mobile/src/lib/pairing.ts` exports `apiBase(host)`:

- Browser dev (no `__TAURI_INTERNALS__` on `window`): returns `''`
  so all fetches are same-origin and use the Vite proxy.
- Tauri native: returns `<scheme>://<desktopHost>` from the pairing
  state.

`apiFetch`, `redeemPairToken`, `devQuickPair`, and `sync-stream` all
use this — don't hard-code `http://localhost:3055` or any other host.
